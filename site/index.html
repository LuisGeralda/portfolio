Configuration analysis

Site Insights

Independent designer & developer

I built Site Insights to replace manual site-by-site configuration review with cell inventories, mobility and CA / EN-DC relation tables, and configuration comparisons.

ImpactUsed internally at Nokia with Apple’s wireless team in Cupertino, Sunnyvale, and Munich. Daily / weekly configuration reports reduce manual preparation for client planning; backup comparisons support Nokia engineers in troubleshooting misconfigurations and tracking daily changes.

  • Python
  • lxml
  • pandas
  • openpyxl
Project details+

Problem

Nokia engineers had to manually inspect each eNB / gNB configuration to review settings and plan client updates or removals. Clients also needed current configuration inventories for planning, while engineers needed a way to identify changes between backups.

My ownership

I independently designed and implemented the configuration-analysis and comparison tool to replace manual site-by-site inspection.

Implementation

I built a Python pipeline that parses SCF / XML managed objects into typed inventories, resolves source-to-target candidates, and evaluates handover, reselection, redirection, and EN-DC dependencies. The reporting pipeline also integrates LTE and NR FR1 standalone carrier-aggregation analysis.

Design decisions

Classify mobility candidates as OK, PARTIAL, NOT CONFIGURED, BLOCKED, or AMBIGUOUS, retaining reason summaries and source-object references. Treat redirection as carrier-based so multiple cells on one target carrier do not create false ambiguity.

Verification

The existing 99-test suite passed on an isolated copy during this portfolio review. Synthetic fixtures exercise missing measurement objects, disabled features, ambiguous targets, EN-DC dependencies, workbook generation, and XML / Excel comparisons.

Operational workflow

The tool is used in a daily configuration-backup workflow. Comparing XML snapshots or generated inventories reveals added, removed, and changed configurations. Daily / weekly reports let clients plan from current configurations and help engineers review changes alongside troubleshooting.

Output

A concise client workbook presents configuration inventories and relations; a detailed internal workbook retains dependency decisions and parameter-level troubleshooting. The documented offline Windows package supports environments without a separate Python installation or runtime internet connection.

Scope & limitations

Configuration eligibility is evidence about the configured network, not proof that a handover succeeds over the air. Customer configurations and outputs are excluded from this portfolio.

03 / ProtocolSep 2026
Desktop + web application

DTLog

End-to-end designer & developer

I designed and implemented DTLog end to end to analyze multiple drive-test captures and calculate campaign KPIs and success rates from procedure counters.

ImpactGives field-test and network-performance teams KPI feedback at the drive-test site without first transferring dozens of large captures to R&D for analysis. Used in Nokia engagements across the Middle East and Africa, particularly Ethiopia.

  • Python
  • FastAPI
  • React
  • TShark
Project details+

Problem

Field and network-performance teams need KPI feedback while still at the drive-test site. Sending dozens of large captures to an R&D location delays analysis. Repeated messages and incomplete procedures also make raw message counts unreliable.

Implementation

I designed and implemented the capture-ingestion workflow, decoder and procedure-analysis engine, FastAPI / React dashboard, and Excel reporting. The engine uses retransmission deduplication, state-machine detection, and decoded cause codes.

Design decisions

Give each signaling event one procedure owner. Pool KPI numerators and denominators before calculating rates. Keep indeterminate outcomes separate from observed failures, and show counts when samples are too small for a useful percentage.

Output

Provides campaign-level KPI feedback at the drive-test site and connects findings to individual procedures and their evidence. Decode caching supports repeated analysis without dissecting the same capture again.

Scope & limitations

NR frames can be decoded, but NR procedure segmentation is not implemented. Missing radio metrics are reported as unavailable rather than estimated. Source and capture sets are private.

08 / MLAug 2024
Applied machine learning

LTE KPI clustering

Apply K-means to LTE RSRP, RSRQ, and throughput data to identify heterogeneous coverage regions and cell-edge performance gaps.

  • Python
  • K-means
  • LTE KPIs
  • Jupyter
Project details+

Problem

A network-wide average can hide local coverage and performance differences. Measurement groups can help reveal regions that deserve a closer RF investigation.

Implementation

I applied K-means clustering to LTE signal and throughput measurements and visualized the resulting coverage regions. The repository includes the notebook, Python implementation, and cluster-map outputs.

Design decisions

Use clustering as an exploratory tool. Interpret clusters against the underlying radio measurements rather than treating a cluster label as a network fault diagnosis.

Output

Identified coverage and cell-edge performance gaps and used them to recommend parameter changes in a proof of concept.

Scope & limitations

This is an exploratory proof of concept. Its findings depend on the dataset and feature selection and should be validated through additional measurements before deployment.
