01 / ProtocolSep 2026
Desktop + web application

DTLog

Analyze UE baseband log captures, reconstruct signaling procedures, and calculate coverage, mobility, accessibility, and voice KPIs across drive-test campaigns.

  • Python
  • FastAPI
  • React
  • TShark
Project details+

Problem

A capture contains repeated messages, incomplete procedures, and unreadable outcomes. Counting messages or averaging per-log percentages can produce confident but misleading network KPIs.

Implementation

I built a decoder and procedure-analysis engine with retransmission deduplication, state-machine detection, decoded cause codes, and a FastAPI / React dashboard. Campaign results are also available as Excel reports.

Design decisions

Give each signaling event one procedure owner. Pool KPI numerators and denominators before calculating rates. Keep indeterminate outcomes separate from observed failures, and show counts when samples are too small for a useful percentage.

Output

Connects campaign-level findings to individual procedures and their evidence. Decode caching supports repeated analysis without dissecting the same capture every time.

Scope & limitations

NR frames can be decoded, but NR procedure segmentation is not implemented. Missing radio metrics are reported as unavailable rather than estimated. Source and capture sets are private.

02 / RANJun 2026
Configuration analysis

Site Insights

Transform Nokia SCF / XML configurations into LTE and NR inventories, mobility relation matrices, carrier-aggregation checks, and snapshot comparisons.

  • Python
  • lxml
  • pandas
  • openpyxl
Project details+

Problem

A configured neighbor does not guarantee a usable mobility path. Feature flags, measurements, target dependencies, and cell relationships need to be checked together.

Implementation

I independently developed configuration-analysis automation for weekly LTE / NR inventories and repeatable lab reviews. The tools inspect intra-frequency, inter-frequency, and inter-RAT mobility, reselection, redirection, and carrier aggregation.

Design decisions

Separate successful paths from blocked or incomplete configurations. Preserve the reasons behind each decision, and compare both XML snapshots and generated inventories to expose changes.

Output

Generates client and internal relation workbooks and identifies added, removed, and changed parameters and relationships. An offline Windows package supports environments without a Python installation or runtime internet access.

Scope & limitations

Configuration eligibility is evidence about the configured network, not proof that a handover succeeds over the air. Customer configurations and outputs are excluded from this portfolio.

03 / RANMay 2026
Android application

Cellular Analyzer

Collect device-exposed LTE / NR measurements with GPS location, retain drive-test sessions, and export measurements for coverage analysis.

  • Kotlin
  • Jetpack Compose
  • Android telephony
  • GPS / CSV
Project details+

Problem

Radio measurements are more useful when they can be connected to where the device was and what it was doing, rather than read as isolated signal values.

Implementation

I developed an Android application using telephony APIs to collect available RSRP, RSRQ, SINR, PCI, cell identity, and frequency information alongside GPS location. Foreground-service logging supports measurement collection with the screen off.

Design decisions

Use device-exposed measurements and keep availability explicit. Local session storage and CSV export make measurements portable for later analysis instead of tying the data to one view.

Output

Combines route visualization, measurement logging, and export in a field-oriented application. The measurement stream can be correlated with drive-test routes during post-test coverage review.

Scope & limitations

Android measurement availability depends on the device, modem, and OS version. Device-exposed metrics do not replace a dedicated RF measurement instrument. The repository is private.

04 / MLAug 2024
Applied machine learning

LTE KPI clustering

Apply K-means to LTE RSRP, RSRQ, and throughput data to identify heterogeneous coverage regions and cell-edge performance gaps.

  • Python
  • K-means
  • LTE KPIs
  • Jupyter
Project details+

Problem

A network-wide average can hide local coverage and performance differences. Measurement groups can help reveal regions that deserve a closer RF investigation.

Implementation

I applied K-means clustering to LTE signal and throughput measurements and visualized the resulting coverage regions. The repository includes the notebook, Python implementation, and cluster-map outputs.

Design decisions

Use clustering as an exploratory tool. Interpret clusters against the underlying radio measurements rather than treating a cluster label as a network fault diagnosis.

Output

Identified coverage and cell-edge performance gaps and used them to recommend parameter changes in a proof of concept.

Scope & limitations

This is an exploratory proof of concept. Its findings depend on the dataset and feature selection and should be validated through additional measurements before deployment.
